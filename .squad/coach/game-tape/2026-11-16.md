# Game tape — 2026-11-16 · Pocket Money v0.1 go-live

**Result:** idea (voice notes + brief) → live private family PWA at https://pocketmoney.nl-dot.com in one day. 104 tests, two Vera gates (both FAIL → fixed → PASS), private repo trust-fullstop/pocket-money.

**What worked**
- Contract-first (types.ts + api.ts + SQL perimeter) let 5 builders run in parallel on disjoint folders with almost no merge pain.
- PGlite = real Postgres in tests *and* the in-browser demo: 104 tests on the exact SQL that went to Supabase; demo lets the family try everything with zero setup.
- Kryptonite before build and Vera before ship both caught real issues (account takeover via re-link QR, siblings seeing allowance, first-visitor family claim, recurrence re-open fines).

**What hurt**
- The second fan-out was **cancelled silently** and Superman reported "squad is building" for ~15 min without checking `list_agents`. Lesson: verify agents are *running* (not just launched) before telling Steve; check after any interruption.
- Parallel Playwright calls across tabs raced (navigations landed in the wrong tab). One browser action at a time, always.
- OAuth device/consent flows timed out repeatedly because the CLI listener was killed by shell cleanup; detached processes fixed it.

## Late evening — second currency (EUR ↔ ZAR)

Steve pays in one currency; the kids buy in another. Shipped "Also show money in" (family rule), live ECB rate (Frankfurter v2, fallback open.er-api, 6 h cache), "≈ R …" on balances/pocket money/goals/bank, a wallet card with a two-way calculator, type-in-the-other-currency on pocket money, requests and goals, and bank balances with their own currency (migration 001600). Kryptonite ran in parallel with the build and changed the bank model (accounts = name + currency). Vera: PASS with two non-blocking fixes (freeze the rate while typing; clear the second currency when it equals the family currency).

**Play of the game:** looking at live data before the final step. Steve had already joined and switched the family currency to ZAR, with amounts typed in rand. Writing "spend in ZAR" would have been a no-op; worse, assuming EUR and converting would have corrupted his numbers. The setting was reworded to be direction-neutral and the decision handed back to Steve.

**Lesson:** once a real user is on the live system, read their data before any "helpful" data write. Ask before changing a family's currency.
